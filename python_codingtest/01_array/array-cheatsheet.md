배열/리스트 기반 코테 문제는 대개 아래 4가지 축으로 귀결됩니다.

1. **카운팅(빈도 집계) → 누적/감산 → 정렬**
2. **정렬 + 키 함수로 순서 결정**
3. **시뮬레이션(상태 업데이트) + 중복 제거(set/map)**
4. **누적합/투포인터/DP로 O(N²) → O(N) 축소**

시험장에서 전형이 안 떠오를 때는 “문제 문장을 보고 단서를 뽑아” 위 축 중 어디에 속하는지 먼저 분류해야 합니다.

---

## 1) 단서로 푸는 방식 분류하기

### A. “몇 명/몇 번/몇 개” 같은 표현이 많다 → 카운팅

* “스테이지별 도전자 수”, “종류별 개수”, “빈도”, “횟수”, “중복”
* 입력 크기가 크고, 매번 스캔하면 느릴 것 같으면:
  **한 번에 세어두는 배열/딕셔너리(빈도표)** 가 거의 정답이다.

### B. “정렬해서 ~ 순으로” “상위 k개” → 정렬 + 키

* 정답이 “순서” 또는 “랭킹”이면 정렬이 중심이다.
* 정렬 전에 필요한 건 보통 **각 원소의 점수/지표 계산**(실패율, 점수, 거리 등).

### C. “이동/경로/좌표/게임판” → 시뮬레이션 + set/map

* 상태(x,y), board, index를 한 스텝씩 업데이트한다.
* “처음 방문/중복 제외/유일한 경로 수” 같은 말이 나오면
  **set으로 중복 제거**가 강력한 후보.

### D. “연속 구간” “부분 배열” “최대/최소 길이” → 투포인터/누적합

* “연속된”이 핵심 단어면 카운팅보다 먼저 이쪽을 의심한다.

## 2) 예시 1: 실패율(카운팅 + 감산 + 정렬) — 왜 이 방식이 자연스럽나

### 문제 구조를 한 문장으로 번역

* “각 스테이지 i에서 **실패한 사람 수 / 도전한 사람 수(= i 이상 도달자)** 를 구해 **내림차순 정렬**한다.”

여기서 바로 단서가 2개 나옵니다.

* “스테이지별” → **그룹별 카운팅**
* “실패율 계산 후 정렬” → **지표 계산 + 정렬**

### 핵심 아이디어가 왜 `challenger` 배열인가

`stages`는 “각 유저가 현재 멈춘 스테이지” 리스트입니다.
즉, `challenger[s]` = “스테이지 s에서 멈춘(실패한) 사람 수”를 만들면:

* 실패자 수는 바로 알 수 있음: `challenger[i]`

그런데 도전자 수는?

* 스테이지 i에 **도달한 사람 수** = “현재 i 이상에 있는 사람 수”
* 이걸 매번 세면 O(N * len(stages))로 커질 수 있으니,
  `total`을 두고 매 스테이지마다 **감산**합니다.

### 감산(`total -= challenger[i]`)이 왜 맞나

* i 스테이지 도전자 수 = “i 이상 도달자 수” = `total`
* i에서 실패한 사람 수 = `challenger[i]`
* 다음 스테이지(i+1) 도전자 수는
  i에서 실패한 사람들은 (i+1)에 못 가므로 `total - challenger[i]`

그래서 이 루프가 성립합니다.

### 시간복잡도 관점(시험장에서 확신하는 포인트)

* `challenger` 채우기: O(len(stages))
* 실패율 계산: O(N)
* 정렬: O(N log N)
  → 입력이 커져도 안정적인 형태(대부분 코테에서 의도한 풀이)

## 3) 예시 2: 방문 경로 수(시뮬레이션 + set) — 왜 set이 단서인가

### 문제 구조를 한 문장으로 번역

* “명령(dirs)대로 이동하면서, **지나간 ‘길(간선)’의 중복을 제거한 개수**를 구한다.”

여기서 단서가 2개 나옵니다.

* “이동/좌표” → **시뮬레이션**
* “중복 제거한 개수” → **set(해시 기반)**

### 왜 점(좌표)을 set에 넣으면 안 되고 “길(간선)”을 넣어야 하나

방문한 점의 개수를 묻는 문제가 아니라, “지나간 길”이므로
(0,0)→(0,1) 과 (0,1)→(0,0)은 같은 길입니다.

따라서 저장해야 할 단위는:

* 노드(점)가 아니라 엣지(길): `(x, y, nx, ny)`

### 왜 양방향을 둘 다 넣는가

길은 무방향이므로,

* (A→B)와 (B→A)를 같은 것으로 취급해야 중복 제거가 정확해집니다.
  가장 단순한 방법이 둘 다 set에 넣고 마지막에 2로 나누는 것입니다.

### 경계 체크가 왜 이 위치에 있나

* -5~5 범위를 벗어나는 이동은 “무시”
* 그래서 nx, ny가 유효할 때만 set에 기록하고 좌표 갱신합니다.

### 시간복잡도 관점

* dirs를 한 번 순회: O(len(dirs))
* set 삽입/조회 평균 O(1)
  → 전체 O(len(dirs))

## 4) 시험장에서 “전형이 안 떠오를 때” 쓰는 강제 루틴

### Step 1: 답의 형태를 먼저 본다

* “정렬된 리스트/순위” → 정렬이 마지막 단계
* “개수” → 카운팅 또는 set
* “최대/최소” + “연속” → 투포인터/누적합 후보
* “상태가 변함(좌표/보드)” → 시뮬레이션 후보

### Step 2: 입력을 한 번만 훑어서 만들 수 있는 보조 구조가 있는지 찾는다

* “스테이지별/종류별/값 범위가 작음” → 배열 카운팅
* “값 범위가 큼/문자열 키” → dict 카운팅

### Step 3: “중복 제거”가 보이면 set을 가장 먼저 떠올린다

* 유일한 경로/유일한 조합/방문 기록/중복 제외

### Step 4: 정렬이 필요하면 “정렬 키”를 분리해서 생각한다

* 먼저 점수/지표를 계산하고
* 그 지표로 정렬한다

---

## 5) 당신 예시를 전형으로 압축하면

* 실패율 문제
  “그룹별 카운팅(배열/딕트) → 누적/감산으로 분모 관리 → 키 정렬”

* 경로(방문 길) 문제
  “시뮬레이션(좌표 갱신) → ‘기록 단위’가 점인지 길인지 확정 → set으로 유일성 처리”

---

원하면, 당신이 실제로 자주 마주치는 프로그래머스/백준 유형을 기준으로
“배열 문제를 6가지 패턴(카운팅/누적합/투포인터/정렬/시뮬레이션/그리디)으로 분류하는 체크리스트”를 더 짧게 만들어 드릴 수 있습니다.
